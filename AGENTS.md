## 1. The project

Natural Trees is a Minecraft 1.21.1 mod for NeoForge and Fabric. It replaces vanilla trees with fully procedural ones: a Weber & Penn skeleton, thickness from a pipe model, a thin connecting branch block that behaves as a log, and foliage computed from the same skeleton. Leaves, decay, saplings and decorators stay vanilla.

You are building it phase by phase, starting from a project skeleton generated by IntelliJ IDEA, with a human who runs the game.

## 3. Who does what

**You** write the code, run Gradle from the command line where your environment allows it, run the unit tests, and read the decompiled Minecraft sources to check facts.

**The human** runs the game from IntelliJ IDEA (the Fabric and NeoForge client run configurations), looks at the result, and sends back logs and screenshots. You cannot see the game. Every in-game check therefore goes to the human as a **manual test script**:

```
Manual test P1-3 — branch arms (Fabric)
1. Run configuration: Fabric Client. Create a creative, superflat world.
2. Place an oak branch against an oak log, then a second branch against the first.
3. Expect: one arm from the first branch into the log; the two branches joined by arms; no arm toward air.
4. Use shears on the top face of the second branch. Expect: an arm appears pointing up.
5. Send back: a screenshot, and any line in logs/latest.log containing "naturaltrees" at WARN or ERROR.
```

If a Gradle command fails for a reason that belongs to your environment (no network, no JDK 21, no display), say so at once and hand the exact command to the human. Do not guess at its output.

## 5. After Milestone 0: follow the spec's roadmap

Work through spec section 18 one phase at a time. Do not start a phase until the previous phase's exit criteria are met, or the human tells you to move on.

**Phase 0 is pure Java, so drive it yourself with tests.** At minimum, `treecore` tests must prove:

- Same parameters and seed give a byte-identical result (hash of the ordered output). Different seeds differ.
- The pipe-model table in spec 7.2: load 1–3 is a branch, 4–15 a 1×1 log, 16 and more a 2×2 trunk; thickness never increases toward a tip; `trunk_leader`, `trunk_width_min` and `trunk_width_max` behave as written.
- Consecutive branch voxels always share a face. Arms are reciprocal and exist only along the skeleton, never between merely adjacent stems.
- With a `canPlace` that blocks arbitrary regions, no wood floats: every wood voxel is connected to the trunk base.
- Every leaf is within `max_distance` face-steps of wood, measured by an independent breadth-first search in the test. `max_leaves`, `max_tips`, `max_radius` and `smother` are respected.
- The predicates are called in the order of spec 7.5: a test double records that no world read happens for a position outside the area.
- Nothing is cached between trees (spec section 2, principle 1): generating tree B after tree A gives the same B as generating B alone.

Also write a small test utility that dumps a tree as PNG projections (side and top) or as text slices, so you can inspect your own output. It is a test helper, not a feature.

**Before any Phase 1 code relies on a vanilla behaviour,** verify the matching item of spec section 20 in the decompiled 1.21.1 sources. Record each in `docs/assumptions.md`: the item, the verdict, and the class and method you read. If an assumption is false, stop, report it, and propose a fix. Do not work around it silently.

## 6. Hard rules

- Java 21. Minecraft 1.21.1. Mojang mappings. No new runtime dependencies.
- `treecore`: no Minecraft imports, no dependencies, `StrictMath` for transcendental functions, its own seeded PRNG, no `java.util.Random`, no `Math.random`, no wall-clock or hash-order dependence.
- **Fully procedural.** No stamps, templates, pre-grown shapes or results cached between trees. Reusing buffers is fine; reusing results is not.
- Optimise only in ways that leave the output unchanged (spec 7.8).
- Licence hygiene: Apache-2.0 headers on source files, with `Copyright 2026 Nursultan Akim`. Do not read or copy code from Arbaro, Blender Sapling, tree-gen or guita's Branches. Do not copy code from Dynamic Trees. Implement from the spec and the paper.
- Scope: nothing from spec section 22, and nothing the spec does not ask for. No config keys beyond spec 14.3.
- Assets use vanilla textures only. The mod adds none.
- Both loaders build at every commit. Shared code lives in `common`; loader modules stay thin.
- Never weaken or delete a failing test to get a green build. Never stub a feature and report it as done. Anything unfinished is a `TODO(naturaltrees)` comment and a line in your report.
